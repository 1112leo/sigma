# 단계별 구현 기록

전체 명세를 기준으로 기존 정적 MVP를 확장한다. 서버·외부 DB·참가자 관리(P2)는 추가하지 않는다.

## 1단계 — 데이터 구조 (완료)

- `schemaVersion: 1`, 중앙 migration, category와 독립적인 round, 사용·검수 상태, 난이도, 출제자, 인정답안·판정메모·생성/수정 시각.
- `timeLimit`이 기준이며 기존 `seconds`는 호환용으로 함께 저장한다.
- 기존 localStorage 키와 JSON 백업을 유지한다. 신규 버전/손상 데이터는 자동 덮어쓰지 않는다.
- 기존 ID, 순서, 제목, 본문, 정답, 해설, 이미지, 진행 메모와 빈 설정값을 보존한다.
- 검증: 6개 테스트 통과(설정 회귀 포함), JS 구문 검사, 배포 빌드 성공.

## 2단계 — 문제 관리 (완료)

- 기존 편집 모달에 라운드·검수·출제자·사용상태·난이도·인정답안·판정메모 추가. ID는 읽기 전용.
- 문제/정답/ID 검색, 6종 필터, 미사용 숨김, 전체 검수 통계, 최종 미확정 경고.
- 필터에 보이는 문제 간 위/아래 이동. 현재 문제 ID·타이머·정답 표시를 유지한다.
- 사진 처리 중 입력 보존, 비동기 업로드 경합 방지, 저장 실패 시 편집창과 이전 상태 보존.
- 검증: 11개 자동 테스트, 빌드, 브라우저에서 PIN 1111·필드 저장·최종 확정 필터·빈 부제 저장 후 새로고침 통과. 테스트는 별도 8082 origin에서 수행하여 기존 데이터와 분리.

## 3단계 — 행사 구성과 안내 화면 (완료)

- `schemaVersion: 2`, question/screen 참조 기반 sequence와 저장되는 sequenceIndex. 유형/라운드와 질문 ID는 독립적으로 유지한다.
- 기본 안내 14종과 사용자 화면 추가/편집. 제목·부제의 빈 값과 긴 기존 안내 원문은 보존한다.
- 구성에 문제/화면 추가, 제거, 위/아래 이동, active 기준 자동 구성, 예비 수동 추가 경고.
- 화면에서는 문제/정답/타이머를 숨기며, 다음 항목 미리보기와 라운드/진행 위치를 운영자에게 표시한다.
- 이전/다음은 sequence 항목 이동, A는 정답 공개, R은 시간 초기화. 입력 중 단축키는 무시한다.
- 누락 참조는 안전한 안내로 처리하며 데이터는 유지한다. 잠금 시 대기 화면만 보내고 기존 구성/위치는 변경하지 않는다.
- 기본 화면 문구와 기존 행사 설정 편집기를 양방향으로 연결했다. 송출 데이터는 현재 화면의 공개 필드만 허용한다.
- 검증: 자동 테스트 27개, JS 구문/빌드, 브라우저에서 화면→문제 이동/화면 중 타이머 숨김/위치 복원/안내 부제 빈칸 저장을 확인했다. 독립 검토에서 찾은 경계 용량·긴 안내문·미리보기 번호 불일치도 수정했다.

## 4단계 — 현장 운영 안전장치 (완료)

- `schemaVersion: 3`, 원본 sequence와 분리된 임시 삽입·즉시 송출·복귀 스택·무효/예비 사용 기록.
- 판정/대기/무효/기술 문제 화면은 즉시 송출하고, 복귀 시 정확한 항목과 남은 시간을 일시정지 상태로 복원한다.
- 타이머 이동 안전 잠금, 0~600초 직접 설정, ±5초, 행사 시간/라운드 진행, 최근 2,000개 로그.
- 저장 실패는 원자적으로 취소하며, 타이머 종료로 미저장 편집 폼을 지우지 않는다. 재접속 중 종료된 타이머도 기록한다.
- 검증: 자동 테스트 41개, 독립 검토의 2,000회 혼합 runtime 직렬화 검사, 빌드와 브라우저 PIN 1111 로그인·87초 설정·긴급 화면 연속 전환·정확한 시간 복귀 확인.

## 남은 의존 단계

P2 참가자/탈락/순위 관리는 운영 규칙 확정 전까지 구현하지 않는다.
